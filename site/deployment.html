Production

Two ways to deploy.

Use a Compose file, and Compose pulls the images for you. Or copy a published image path and docker pull it yourself. pnpm deploy:stack and pnpm deploy:standalone still build from a git checkout and ignore OTTERSCALE_IMAGE_TAG.

Option 1

Compose file

Download the file and its env example. Save the example as .env and set OTTERSCALE_IMAGE_TAG. docker compose -f that file --env-file .env up -d pulls the GHCR images and starts them. Stack is four containers on a VM. Standalone is one container.

Stack

Headscale, core, the console, and edge. For a VM with Docker Compose.

otterscale-stack.yaml download
otterscale-stack.env.example download

Standalone

One container. For a VM, or a platform that runs a single image.

otterscale-standalone.yaml download
otterscale-standalone.env.example download

Option 2

Pull an image

Copy an image path and run docker pull, or paste that path into a host that does not run Compose. You do not need the Compose file for this. The latest tag is the current publish.

No published docker images.

A VM with Docker

Use option 1. Security group or firewall: TCP 80 and 443. Point DNS at the console host and the Headscale host.

terminal Any Linux VM keyboard_arrow_down
  1. Install Docker Engine and the Compose plugin.
  2. Download otterscale-stack.yaml or otterscale-standalone.yaml, and the matching env example.
  3. Save the env example as .env. Set OTTERSCALE_IMAGE_TAG, AUTH_SECRET, AUTH_URL, and OTTERSCALE_DOMAIN.
  4. docker compose -f otterscale-stack.yaml --env-file .env up -d, or the standalone file.
  5. Open the console host. The first visit is /setup. The Tailscale login server is the Headscale hostname.
cloud AWS EC2 keyboard_arrow_down
  1. Launch Ubuntu. Security group: TCP 80 and 443.
  2. Install Docker Compose. Copy the stack or standalone file and its env example onto the instance.
  3. Route 53 records for the console and Headscale. Set those names in .env with OTTERSCALE_IMAGE_TAG.
  4. docker compose -f otterscale-stack.yaml --env-file .env up -d, or the standalone file.
  5. Caddy’s certificates are internal. Put a public proxy in front when browsers must trust the console.
deployed_code Azure Virtual Machine keyboard_arrow_down
  1. Create a VM. NSG: TCP 80 and 443. Attach a data disk for Docker volumes.
  2. Install Docker Compose. Copy the stack or standalone file and its env example.
  3. DNS for the console and Headscale. Set OTTERSCALE_DOMAIN and OTTERSCALE_IMAGE_TAG.
  4. docker compose --env-file .env up -d with the file you copied.
dns GCP Compute Engine keyboard_arrow_down
  1. Create a VM. VPC firewall: HTTP and HTTPS. Reserve a static IP.
  2. Cloud DNS for the console and Headscale. Install Docker Compose.
  3. Copy the stack or standalone file and its env example. Set OTTERSCALE_IMAGE_TAG.
  4. Keep host port 8080 on localhost. Clients use the Headscale hostname on 443.
lan DigitalOcean Droplet keyboard_arrow_down
  1. Create a Droplet with Docker, or install Docker Compose. Cloud Firewall: TCP 80 and 443.
  2. Copy the stack or standalone file and its env example. Set OTTERSCALE_IMAGE_TAG and the public hostnames.
  3. docker compose -f otterscale-stack.yaml --env-file .env up -d, or the standalone file.

One container

Use option 2. These hosts run the standalone image and do not run the Compose file. Mount a disk at /data. The platform sets PORT. App Runner, Lightsail Containers, and Heroku cannot keep /data.

route Railway keyboard_arrow_down
  1. One service from ghcr.io/robosushie/otterscale/standalone, tag from the list above.
  2. Volume at /data. Railway sets PORT.
  3. Set AUTH_SECRET, AUTH_URL, OTTERSCALE_DOMAIN, CONSOLE_HOST, and HS_HOST from the standalone env example. Leave the Headscale keys unset.
web_asset Render keyboard_arrow_down
  1. One web service from ghcr.io/robosushie/otterscale/standalone, tag from the list above.
  2. Persistent disk at /data. Render sets PORT.
  3. Set AUTH_URL, OTTERSCALE_DOMAIN, CONSOLE_HOST, and HS_HOST to the public HTTPS hostnames.
flight Fly.io keyboard_arrow_down
  1. One Machine from ghcr.io/robosushie/otterscale/standalone.
  2. Fly volume mounted at /data. Set the public port to the platform PORT.
  3. Same env list as the standalone example. Two hostnames: console and Headscale.
deployed_code DigitalOcean App Platform keyboard_arrow_down
  1. One component from ghcr.io/robosushie/otterscale/standalone.
  2. Attach a volume at /data. The platform sets PORT.
  3. Copy AUTH_SECRET, AUTH_URL, OTTERSCALE_DOMAIN, CONSOLE_HOST, and HS_HOST from the standalone env example.
cloud Azure Container Apps keyboard_arrow_down
  1. One container from ghcr.io/robosushie/otterscale/standalone.
  2. Azure Files mounted at /data. Ingress uses the platform port.
  3. Set the standalone env values. Leave HEADSCALE_API_KEY and APPS_EDGE_AUTHKEY empty.
dns GCP Cloud Run keyboard_arrow_down
  1. One service from ghcr.io/robosushie/otterscale/standalone.
  2. Mount a network disk at /data. Without that disk the Headscale database disappears on the next instance.
  3. Cloud Run sets PORT. Set the standalone env values for the console and Headscale hostnames.
