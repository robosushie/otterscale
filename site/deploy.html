Otterscale Stack

One Compose file. Pull and run.

Images live on GHCR. After Headscale is healthy, bootstrap writes API keys and AUTH_SECRET. Set OTTERSCALE_DOMAIN wherever TLS sits in front of Headscale.

Generic Docker host

Canonical path: a VM with Docker Compose, ports 80/443, and a volume disk.

terminal Linux or cloud VM
  1. Install Docker Engine and the Compose plugin.
  2. Download otterscale-stack.yaml and the env example.
  3. Copy the env example to .env. Production: set OTTERSCALE_DOMAIN and AUTH_URL.
  4. Run docker compose -f otterscale-stack.yaml --env-file .env up -d.
  5. Open https://console.localhost (add a hosts line if needed). First visit: /setup.
  6. On Machines, copy both commands: tailscale logout then tailscale up. Local login-server is http://127.0.0.1:8080.

Cloud platforms

Numbered steps per host. Compose is native on a VM. Railway and Heroku are not one-blob Compose.

cloud AWS EC2
  1. Launch Ubuntu. Security group: TCP 80 and 443 (8080 only if you join from the instance).
  2. Install Docker Compose on the instance.
  3. Copy the stack YAML and env example onto the box (download links above).
  4. Create Route 53 records for console and Headscale. Set OTTERSCALE_DOMAIN, AUTH_URL, CONSOLE_HOST, HS_HOST.
  5. docker compose -f otterscale-stack.yaml --env-file .env up -d.
  6. This stack’s Caddy uses internal TLS. Put a public proxy in front, or swap Caddy to public certs, if browsers must trust the console.
deployed_code Azure Virtual Machine
  1. Create a VM. NSG: TCP 80 and 443.
  2. Attach a data disk and bind Docker volumes there so SQLite and Headscale survive reboot.
  3. Install Docker, copy the stack files, fill .env.
  4. Point DNS at the VM. Set OTTERSCALE_DOMAIN to the Headscale hostname — do not leave it empty in production.
  5. docker compose up -d, then /setup and Add device.
dns GCP Compute Engine
  1. Create a VM. VPC firewall: allow http and https.
  2. Reserve a static IP. Create Cloud DNS records for console and Headscale.
  3. Install Docker, copy stack + env, set OTTERSCALE_DOMAIN.
  4. Keep host :8080 on localhost unless TLS terminates elsewhere.
  5. docker compose up -d. Persistent disk for volumes.
lan Akamai Linode
  1. Use Marketplace Docker or a Debian image. Cloud Firewall: 80/443.
  2. Download the stack YAML and env example onto the instance.
  3. Fill .env (OTTERSCALE_IMAGE_TAG if you pinned a GHCR tag).
  4. Linode DNS for CONSOLE_HOST and HS_HOST.
  5. docker compose -f otterscale-stack.yaml --env-file .env up -d.
web_asset Render
  1. Preferred: a Render VM that can run Docker Compose with the downloaded stack file.
  2. If you split one GHCR image per service, you lose the secrets volume.
  3. Mint keys once: headscale apikeys create and a tag:edge pre-auth key.
  4. Paste HEADSCALE_API_KEY and APPS_EDGE_AUTHKEY into each service.
  5. Set OTTERSCALE_DOMAIN to Render’s public Headscale HTTPS origin (matches Headscale server_url).
route Railway
  1. Do not run this Compose file inside one empty Railway service. There is no shared volume.
  2. Create three services from GHCR: app, edge, headscale.
  3. Private DNS: http://headscale.railway.internal:8080 as HEADSCALE_INTERNAL_URL.
  4. Volume on Headscale and on the app (SQLite).
  5. One-off on Headscale: apikeys create and preauthkeys create --tags tag:edge. Set those vars on app and edge.
  6. Attach a public HTTPS domain to Headscale. Set OTTERSCALE_DOMAIN to that origin. No inbound UDP for your own DERP.
warning Heroku
  1. Heroku is not a Compose host and does not share volumes. This YAML will not run there.
  2. Use a cloud VM (EC2, Lightsail, Linode) for Headscale + edge + app instead.
  3. Download the stack file and follow Generic Docker host.
package_2 Publish GHCR images
  1. GitHub → Actions → Publish GHCR.
  2. Pick the branch. Enter a tag such as 0.1.0 or dev.
  3. That pushes ghcr.io/robosushie/otterscale/{app,edge,headscale}.
  4. Semver tags also move latest. Override with OTTERSCALE_IMAGE_TAG.
  5. If packages stay private, open Packages once and set visibility to public.
