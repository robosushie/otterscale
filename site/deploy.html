Otterscale Stack

Two deploy commands.

pnpm deploy:stack builds the multi-container host. pnpm deploy:standalone builds one container. Pull the standalone image when you are not building from this repo.

Generic Docker host

Canonical path: a VM with Docker Compose, ports 80/443, and a volume disk.

terminal Linux or cloud VM
  1. Install Docker Engine, the Compose plugin, Node 22, and pnpm.
  2. Clone the repo. Production: set OTTERSCALE_DOMAIN and AUTH_URL in .env.
  3. Run pnpm deploy:stack. Add --keep-data to reuse volumes.
  4. Open https://console.localhost (add a hosts line if needed). First visit: /setup.
  5. On Machines, copy both commands: tailscale logout then tailscale up. Local login-server is http://127.0.0.1:8080.
deployed_code One container (standalone)
  1. Same host as above, or Railway/Render as a single service.
  2. Download otterscale-standalone.yaml and the standalone env.
  3. Copy the env example to .env. Set OTTERSCALE_DOMAIN and AUTH_URL in production.
  4. Run docker compose -f otterscale-standalone.yaml --env-file .env up -d, or pnpm deploy:standalone from a git checkout.
  5. PaaS: Dockerfile deploy/standalone/Dockerfile, disk at /data. The platform sets PORT. Set CONSOLE_HOST and HS_HOST to the public hostnames.

Cloud platforms

Numbered steps per host. Compose is native on a VM. Railway and Render should use the standalone image, not the three-service stack.

cloud AWS EC2
  1. Launch Ubuntu. Security group: TCP 80 and 443 (8080 only if you join from the instance).
  2. Install Docker Compose on the instance.
  3. Clone the repo onto the instance.
  4. Create Route 53 records for console and Headscale. Set OTTERSCALE_DOMAIN, AUTH_URL, CONSOLE_HOST, HS_HOST.
  5. pnpm deploy:stack.
  6. This stack’s Caddy uses internal TLS. Put a public proxy in front, or swap Caddy to public certs, if browsers must trust the console.
deployed_code Azure Virtual Machine
  1. Create a VM. NSG: TCP 80 and 443.
  2. Attach a data disk and bind Docker volumes there so SQLite and Headscale survive reboot.
  3. Install Docker and pnpm, clone the repo, fill .env.
  4. Point DNS at the VM. Set OTTERSCALE_DOMAIN to the Headscale hostname — do not leave it empty in production.
  5. pnpm deploy:stack, then /setup and Add device.
dns GCP Compute Engine
  1. Create a VM. VPC firewall: allow http and https.
  2. Reserve a static IP. Create Cloud DNS records for console and Headscale.
  3. Install Docker and pnpm, clone the repo, set OTTERSCALE_DOMAIN.
  4. Keep host :8080 on localhost unless TLS terminates elsewhere.
  5. pnpm deploy:stack. Persistent disk for volumes.
lan Akamai Linode
  1. Use Marketplace Docker or a Debian image. Cloud Firewall: 80/443.
  2. Clone the repo. Fill .env.
  3. Linode DNS for CONSOLE_HOST and HS_HOST.
  4. pnpm deploy:stack.
web_asset Render
  1. Preferred: one web service from ghcr.io/robosushie/otterscale/standalone (or Dockerfile deploy/standalone/Dockerfile).
  2. Attach a persistent disk at /data. Render sets PORT; Caddy listens there.
  3. Set AUTH_URL, OTTERSCALE_DOMAIN, CONSOLE_HOST, and HS_HOST to the public HTTPS hostnames.
  4. A Render VM with Docker and pnpm can run pnpm deploy:stack instead.
  5. If you split one GHCR image per service, you lose the secrets volume and must mint keys by hand.
route Railway
  1. One service from ghcr.io/robosushie/otterscale/standalone (or Dockerfile deploy/standalone/Dockerfile).
  2. Volume at /data. Railway sets PORT; do not run the three-service Compose file here.
  3. Set AUTH_URL, OTTERSCALE_DOMAIN, CONSOLE_HOST, and HS_HOST to the public HTTPS domains on that service.
  4. Bootstrap inside the container mints API keys onto the disk. No inbound UDP for your own DERP.
  5. Split app / edge / headscale only if you need separate services; then mint keys by hand and use private DNS.
warning Heroku
  1. Heroku is not a Compose host and does not share volumes.
  2. Use a cloud VM (EC2, Lightsail, Linode) for Headscale + edge + app instead.
  3. Clone the repo and run pnpm deploy:stack.
package_2 Publish GHCR images
  1. GitHub → Actions → Publish GHCR.
  2. Pick the branch. Enter a tag such as 0.1.0 or dev.
  3. That pushes ghcr.io/robosushie/otterscale/{app,edge,headscale,standalone}.
  4. Semver tags also move latest. Override with OTTERSCALE_IMAGE_TAG.
  5. If packages stay private, open Packages once and set visibility to public.
